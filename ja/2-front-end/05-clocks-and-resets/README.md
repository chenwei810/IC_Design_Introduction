## クロックはどこから来るか

回路基板には水晶発振器があり、とても安定しているものの、周波数はそれほど高くない基準クロックを出しています。チップの中の **PLL** がそれを 500 MHz に逓倍し、MAC アレイ、SRAM、制御回路に送ります。

一方で、CPU はバスを通して `tiny_npu` のレジスタにアクセスし、バスはシステムの 100 MHz のクロックで動いています。だから `tiny_npu` の中には、二つのクロックが同時に存在します。

> [!NOTE]
> **📖 用語｜PLL（Phase-Locked Loop、位相同期回路、鎖相迴路）**
>
> - **定義**：外部の基準クロックを、チップ内部で必要な周波数に逓倍するアナログ回路。
> - **現場での使い方**：PLL はまず「ロック」してからでないと、出力のクロックが安定せず使えない。「PLL はロックした？」はチップの立ち上げで最初に確かめることの一つである。
> - **関連用語**：基準クロック、クロックジッタ、クロックツリー
> - **よくある混同**：PLL は RTL で書くものではなく、買ってきたアナログ IP である。シミュレーションでは、ふつう簡略化した動作モデルで代用する。

## 二つのクロックドメイン

同じクロックで駆動されるすべてのフリップフロップを、一つの**クロックドメイン**と呼びます。`tiny_npu` には二つあります。

- **バス側**（100 MHz）：レジスタインターフェース。ファームウェアが `CTRL` と `LEN` を書き、`STATUS` を読む。
- **演算側**（500 MHz）：制御回路、MAC アレイ、SRAM。

二つのクロックは周波数が違い、位相の関係も決まっていません。これを**非同期**と呼びます。ファームウェアが書いた `START` はバス側から演算側へ、演算側の `DONE` はバス側へ送り返す必要があります。この二つの信号は、どちらもクロックドメインをまたぐ信号です。

> [!NOTE]
> **📖 用語｜クロックドメインとクロックドメインクロッシング（Clock Domain／Clock Domain Crossing、CDC、時脈域與跨時脈域）**
>
> - **定義**：同じクロックで駆動されるフリップフロップの集まりがクロックドメインで、信号があるクロックドメインから別のクロックドメインへ渡ることがクロックドメインクロッシングである。
> - **現場での使い方**：「これは CDC パスだから、シンクロナイザを通して」「テープアウト前に CDC レポートをきれいにしておく」。
> - **関連用語**：シンクロナイザ、非同期 FIFO、メタステーブル
> - **よくある混同**：二つのクロックの周波数が同じでも、発生源が違えば、別のクロックドメインである。

## メタステーブル：撮りかけの写真

第 3 章で、フリップフロップはクロックのエッジでシャッターを押すようなものだと説明しました。シャッターを押したちょうどその瞬間にデータが変わると、写真はぶれます。フリップフロップの出力はしばらく 0 と 1 の間にとどまり、最後にどちらかへランダムに倒れることがあります。これを**メタステーブル**と呼びます。

同じクロックドメインの中なら、第 8 章のタイミング解析が、シャッターの前後でデータが変わらないことを保証します。しかし二つのクロックが非同期だと、誰にも保証できず、メタステーブルはいずれ必ず起きます。

解決方法は**シンクロナイザ**（Synchronizer）です。受け取る側でフリップフロップを 2 個直列につなぎます。1 個目のフリップフロップがぶれた写真を撮っても、ほぼ 1 クロック周期の間に落ち着くことができ、2 個目のフリップフロップが読む値は、ほぼ確実にはっきりした 0 か 1 になります。

```verilog
module sync_2ff (
    input  wire clk,      // clock of the receiving domain
    input  wire rst_n,
    input  wire d,        // comes from another clock domain
    output reg  q
);
    reg meta;             // may go metastable; never use it directly
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) {q, meta} <= 2'b00;
        else        {q, meta} <= {meta, d};
    end
endmodule
```

> [!NOTE]
> **📖 用語｜メタステーブル（Metastability、亞穩態）**
>
> - **定義**：フリップフロップが変化中のデータを取り込んだとき、出力が一時的に 0 と 1 の間にとどまり、なかなか安定しない状態。
> - **現場での使い方**：よく meta と略す。「1 段目の flop は meta になるかもしれないから、直接使わないで」。
> - **関連用語**：シンクロナイザ、setup、hold、平均故障間隔（MTBF）
> - **よくある混同**：メタステーブルは設計の誤りで起きるのではなく、どんなフリップフロップでも起きる。設計がすべきことは、使われる前にそれを落ち着かせることである。

> [!IMPORTANT]
> **💻 ソフトウェアとの対比｜クロックドメインをまたぐのは、二つのスレッドが一つの変数を共有するのに似ている**
>
> - **似ている点**：二つのスレッドがロックをかけずに同じ変数を読み書きすると、競合状態（Race Condition）が起きる。
> - **違う点**：ソフトウェアの競合状態では、読めるのは古い値か新しい値のどちらかである。ハードウェアのメタステーブルでは、出力がしばらく 0 でも 1 でもない状態になり、下流の二つの回路がそれぞれ違う答えを読むことさえある。
> - **だから注意**：シミュレータにはメタステーブルがないので、クロックドメインをまたぐ誤りをシミュレーションで捕まえるのはほぼ不可能である。クロックドメインをまたぐ信号はどれもシンクロナイザを通し、CDC チェックツールで 1 本ずつ確認する。

<details>
<summary>🔍 もう一歩深く：シンクロナイザはなぜ 2 段なのか</summary>

メタステーブルはとても速く消えていきます。フリップフロップに落ち着くための時間を少し多く与えるごとに、まだ落ち着いていない確率は指数関数的に下がります。設計者はシンクロナイザを**平均故障間隔**（Mean Time Between Failures、MTBF）で評価します。平均してどれくらいの間隔で 1 回失敗するか、という値です。

フリップフロップ 1 個だけでは、落ち着くための時間はほとんどゼロで、MTBF は数秒しかないかもしれません。2 段目をつなげば、ほぼまる 1 クロック周期の余裕が生まれ、MTBF はチップの寿命をはるかに超えるほど長くなります。クロックがとても速いチップや、信頼性への要求が極めて高いチップでは、3 段までつなぎます。

ライブラリには、ふつう専用のシンクロナイザセルが用意されています。中の二つのフリップフロップをごく近くに置き、メタステーブルに対して最適化したものです。

</details>

1 ビットだけの制御信号なら、シンクロナイザで扱えます。複数ビットのデータは厄介です。

> [!TIP]
> **🔧 ノウハウ｜複数ビットのデータは、ビットごとに別々に同期してはいけない**
>
> - **状況**：ファームウェアがバス側で `LEN` を書き、演算側がその数を読みたい。
> - **やり方**：まず `LEN` を変わらないように保ち、1 ビットの `START` だけをシンクロナイザで送る。演算側は `START` を受け取ってから `LEN` を読む。このやり方を**ハンドシェイク**（Handshake）と呼ぶ。大量の連続したデータには**非同期 FIFO** を使う。
> - **理由**：ビットごとのシンクロナイザは、それぞれ違うクロック周期で落ち着くことがある。
> - **やらないとどうなる**：ちょうど `LEN` が変わるクロックで、演算側が古いビットと新しいビットの混ざった値を読み、古い値でも新しい値でもない数を受け取ることがある。この種の誤りはめったに起きず、起きたときには再現がとても難しい。
> - **関連する章**：[第 15 章　チップが戻ってきたら](../../4-to-the-fab/15-after-silicon/README.md)

## リセット：チップを既知の状態から始める

電源を入れた直後は、どのフリップフロップの値もでたらめです。**リセット**（Reset）は、それらを決まった初期値にします。たとえば状態機械を `IDLE` に戻し、累算器を 0 にします。

`mac` が使うのは**非同期リセット**です。`rst_n` が下がれば、クロックを待たずに、フリップフロップはすぐ 0 になります。リセットに入るのは問題ありません。厄介なのはリセットを解除する瞬間です。解除のタイミングがちょうどクロックのエッジに近いと、あるフリップフロップはこのクロックでリセットを抜け、別のフリップフロップは次のクロックで抜けます。状態機械は最初から道を誤るかもしれません。

> [!TIP]
> **🔧 ノウハウ｜リセットは非同期で入り、同期で抜ける**
>
> - **状況**：外部のリセット信号はボタンや電源管理回路から来て、チップの中のクロックとは関係がない。
> - **やり方**：クロックドメインごとに**リセットシンクロナイザ**を一つずつ置く。リセットが来たらすぐにそのクロックドメイン全体をリセットに入れ、解除はそのクロックドメインのクロックのエッジにそろえる。
> - **理由**：こうすれば、同じクロックドメインのすべてのフリップフロップが、同じクロックのエッジで一斉にリセットを抜ける。
> - **やらないとどうなる**：チップがときどき起動に失敗する。しかも温度、電圧、さらにはチップの個体によって起きたり起きなかったりする。このような問題は実験室で再現するのが難しい。
> - **関連する章**：[第 15 章　チップが戻ってきたら](../../4-to-the-fab/15-after-silicon/README.md)

## クロックゲーティング：働かないなら、クロックを止める

クロックは毎クロック切り替わる、チップの中で最も頻繁に切り替わる信号です。第 2 章で述べたとおり、切り替われば電力を使います。だからクロックとフリップフロップは、チップの動的電力の大きな部分を占めることがよくあります。

ファームウェアがまだ命令を出していないとき、MAC アレイにはすることがないのに、クロックはいつもどおり動いています。**クロックゲーティング**（Clock Gating）は、こういうときに MAC アレイ全体のクロックを止め、`START` が来たら再び動かす技術です。

クロックゲーティングには、ライブラリにある専用の**統合クロックゲーティングセル**（Integrated Clock Gating Cell、ICG）を使います。手近な AND ゲートで済ませてはいけません（第 3 章）。論理合成ツールは、RTL の中のイネーブル条件から自動的にクロックゲーティングを挿入することもできます。これが本書で最初に出てくる、RTL のレベルで行う低消費電力の技術で、第 10 章と第 13 章でも取り上げます。

---

## この章のポイント

1. チップのクロックは、PLL が外部の基準クロックを逓倍して作る。`tiny_npu` にはバス側と演算側の二つのクロックドメインがある。
2. クロックドメインをまたぐ信号は、フリップフロップをメタステーブルにすることがある。1 ビットなら 2 段のシンクロナイザを、複数ビットならハンドシェイクか非同期 FIFO を使う。
3. シミュレータにはメタステーブルが見えないので、クロックドメインをまたぐ信号は CDC チェックツールで 1 本ずつ確認する。
4. リセットは非同期で入り、同期で抜ける。クロックドメインごとにリセットシンクロナイザを一つ置く。
5. クロックゲーティングはブロックが暇なときにクロックを止める、最もよく使われる省電力の方法の一つである。
