## 時脈從哪裡來

電路板上有一顆石英振盪器，提供一個很穩定、但頻率不高的參考時脈。晶片裡的 **PLL** 把它倍頻成 500 MHz，送給 MAC 陣列、SRAM 和控制電路。

另一邊，CPU 透過匯流排存取 `tiny_npu` 的暫存器，匯流排跑的是系統的 100 MHz 時脈。所以 `tiny_npu` 裡同時有兩個時脈。

> [!NOTE]
> **📖 名詞｜鎖相迴路（Phase-Locked Loop，PLL）**
>
> - **定義**：把外部的參考時脈，倍頻成晶片內部需要的頻率的類比電路。
> - **現場用法**：PLL 要先「鎖住」，輸出的時脈才穩定可用，例如「PLL lock 了沒？」是點亮晶片時最先確認的事情之一。
> - **相關名詞**：參考時脈、時脈抖動、時脈樹
> - **常見混淆**：PLL 不是用 RTL 寫出來的，而是買來的類比 IP。模擬時通常用一個簡化的行為模型代替它。

---

## 兩個時脈域

同一個時脈驅動的所有正反器，叫做一個**時脈域**。`tiny_npu` 有兩個：

- **匯流排側**（100 MHz）：暫存器介面。韌體寫入 `CTRL`、`LEN`，讀取 `STATUS`。
- **運算側**（500 MHz）：控制電路、MAC 陣列與 SRAM。

兩個時脈的頻率不同，彼此的相位也沒有固定關係，叫做**非同步**。韌體寫下的 `START`，要從匯流排側送到運算側；運算側的 `DONE`，要送回匯流排側。這兩條訊號都是跨時脈域的訊號。

> [!NOTE]
> **📖 名詞｜時脈域與跨時脈域（Clock Domain／Clock Domain Crossing，CDC）**
>
> - **定義**：同一個時脈驅動的一群正反器叫一個時脈域；訊號從一個時脈域傳到另一個，叫跨時脈域。
> - **現場用法**：「這條是 CDC path，要過同步器」「下線前 CDC 報告要清乾淨」。
> - **相關名詞**：同步器、非同步 FIFO、亞穩態
> - **常見混淆**：兩個時脈即使頻率一樣，只要來自不同的來源，仍然是不同的時脈域。

## 亞穩態：拍到一半的照片

第 3 章說過，正反器像在時脈邊緣按下快門。如果資料剛好在按下快門的那一刻改變，照片就會拍糊。正反器的輸出可能停在 0 和 1 之間一段時間，最後才隨機倒向其中一邊。這叫做**亞穩態**。

在同一個時脈域裡，第 8 章的時序分析會確保資料不會在快門前後改變。但兩個時脈非同步時，誰也無法保證，亞穩態遲早會發生。

解決方法是**同步器**（Synchronizer）：在接收端串兩個正反器。第一個正反器就算拍糊了，也有將近一個時脈週期可以穩定下來，第二個正反器讀到的就幾乎一定是清楚的 0 或 1。

```verilog
module sync_2ff (
    input  wire clk,      // clock of the receiving domain
    input  wire rst_n,
    input  wire d,        // comes from another clock domain
    output reg  q
);
    reg meta;             // may go metastable; never use it directly
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) {q, meta} <= 2'b00;
        else        {q, meta} <= {meta, d};
    end
endmodule
```

> [!NOTE]
> **📖 名詞｜亞穩態（Metastability）**
>
> - **定義**：正反器讀入正在改變的資料時，輸出暫時停在 0 和 1 之間、遲遲無法穩定的狀態。
> - **現場用法**：常簡稱 meta，例如「第一級 flop 可能 meta，不要直接拿去用」。
> - **相關名詞**：同步器、setup、hold、平均故障間隔（MTBF）
> - **常見混淆**：亞穩態不是設計錯誤造成的，任何正反器都會發生。設計要做的是讓它在被使用之前就穩定下來。

> [!IMPORTANT]
> **💻 軟體對照｜跨時脈域，像兩個執行緒共用一個變數**
>
> - **像什麼**：兩個執行緒不加鎖就讀寫同一個變數，會發生競爭條件（Race Condition）。
> - **不一樣的地方**：軟體的競爭條件，讀到的不是舊值就是新值。硬體的亞穩態，輸出可能有一段時間不是 0 也不是 1，下游兩個電路甚至會各自讀到不同的答案。
> - **所以要注意**：模擬器裡沒有亞穩態，所以跨時脈域的錯誤幾乎不可能靠模擬抓到。每一條跨時脈域的訊號，都要經過同步器，並用 CDC 檢查工具逐條確認。

<details>
<summary>🔍 深入一點：同步器為什麼是兩級</summary>

亞穩態消退得很快：每多給正反器一點穩定的時間，它還沒穩定下來的機率就以指數下降。設計者用**平均故障間隔**（Mean Time Between Failures，MTBF）來評估同步器，也就是平均多久會失敗一次。

只用一個正反器，留給它穩定的時間幾乎是零，MTBF 可能只有幾秒。串上第二級，就多出將近一整個時脈週期，MTBF 可以拉長到遠遠超過晶片的壽命。時脈非常快、或對可靠度要求極高的晶片，會串到三級。

元件庫通常會提供專門的同步器元件，內部的兩個正反器擺得很近，並針對亞穩態最佳化。

</details>

只有一個位元的控制訊號，可以用同步器處理。多個位元的資料就麻煩了：

> [!TIP]
> **🔧 Know-how｜多位元的資料，不能每一位元各自同步**
>
> - **情境**：韌體在匯流排側寫入 `LEN`，運算側要讀到這個數字。
> - **做法**：先讓 `LEN` 保持不動，再只把一個位元的 `START` 經過同步器送過去；運算側收到 `START` 之後，才去讀 `LEN`。這種做法叫**交握**（Handshake）。大量連續的資料則用**非同步 FIFO**。
> - **為什麼**：每一位元的同步器，可能在不同的時脈週期才穩定下來。
> - **沒做會怎樣**：`LEN` 剛好在變的那一拍，運算側可能讀到一部分舊位元、一部分新位元，得到一個既不是舊值、也不是新值的數字。這種錯誤很少發生，一發生就很難重現。

## 重置：讓晶片從已知的狀態開始

剛通電時，每個正反器的值都是隨機的。**重置**（Reset）把它們設定成已知的初始值，例如讓狀態機回到 `IDLE`、累加器歸零。

`mac` 用的是**非同步重置**：`rst_n` 一拉低，不必等時脈，正反器就立刻歸零。進入重置沒有問題，麻煩在解除重置的那一刻。如果解除的時間剛好靠近時脈邊緣，有些正反器會在這一拍離開重置，有些在下一拍，狀態機可能一開始就走錯。

> [!TIP]
> **🔧 Know-how｜重置要非同步進入、同步解除**
>
> - **情境**：外部的重置訊號來自按鈕或電源管理電路，和晶片裡的時脈沒有關係。
> - **做法**：每個時脈域各放一個**重置同步器**。重置一來，馬上讓整個時脈域進入重置；解除時，則對齊這個時脈域的時脈邊緣。
> - **為什麼**：這樣同一個時脈域裡的所有正反器，會在同一個時脈邊緣一起離開重置。
> - **沒做會怎樣**：晶片偶爾開機失敗，而且和溫度、電壓、甚至是哪一顆晶片有關。這類問題在實驗室裡很難重現。

## 時脈閘控：不工作，就別讓時脈跑

時脈每一拍都在切換，是晶片裡切換最頻繁的訊號。第 2 章說過，切換就要耗電。所以時脈和正反器，常常吃掉晶片動態功耗的一大部分。

韌體還沒下指令時，MAC 陣列沒事做，時脈卻照樣在跳。**時脈閘控**（Clock Gating）就是在這時候把整片 MAC 陣列的時脈關掉，等 `START` 進來再打開。

時脈閘控要用元件庫裡專用的**整合式時脈閘控元件**（Integrated Clock Gating Cell，ICG），不能隨手用一個 AND 閘（第 3 章）。合成工具也能從 RTL 裡的致能條件，自動插入時脈閘控。這是這本書第一個在 RTL 層級做的低功耗技巧，第 10 章和第 13 章還會再談。

## 本章重點

1. 晶片的時脈由 PLL 從外部參考時脈倍頻而來；`tiny_npu` 有匯流排側與運算側兩個時脈域。
2. 跨時脈域的訊號可能讓正反器進入亞穩態；單一位元用兩級同步器，多位元用交握或非同步 FIFO。
3. 模擬器看不到亞穩態，跨時脈域要靠 CDC 檢查工具逐條確認。
4. 重置要非同步進入、同步解除，每個時脈域各有一個重置同步器。
5. 時脈閘控在區塊閒置時關掉時脈，是最常用的省電方法之一。
